# Troubleshooting Modstoke Loader

**Publication status (15 October 2026):** The new public Loader repository was started with a README only. This guide refers to files in a separate, prepared local source checkout and to a Loader package built from it. It does not imply that the repository offers an installable release.

The checks below follow the current package script and runtime state paths. Begin with the first error you see; later Loader state files will not exist if startup stopped in the native host.

## The package will not build

| Symptom | What to check |
| --- | --- |
| `GameRoot does not look like a Sons Of The Forest install` | Point `-GameRoot` at the folder containing `SonsOfTheForest.exe`, not the executable or `SonsOfTheForest_Data` folder. |
| `RedLoader/SonsSdk support assemblies were not found` | Build or restore the sibling `RedLoader/SonsSdk` output. The script checks for `RedLoader/SonsSdk/bin/Debug/net6/SonsSdk.dll` and packages its matching compatibility assemblies. |
| Core says `GameInteropRoot must contain the complete generated IL2CPP wrapper set` | Use a prepared game install whose `BepInEx/interop` wrappers were generated by the Loader, or point `GameInteropRoot` at an existing complete generated set. Do not substitute Unity base libraries or commit game-derived wrappers. |
| `.NET ... runtime` or `hostfxr` was not found | Check the exact runtime version in `openacai-loader.manifest.json`. Supply `-DotnetRoot` with the matching SDK/runtime if it is not installed in a location the script searches. Another .NET 11 build is not interchangeable here. |
| `llvm-readobj was not found` | Add LLVM's `llvm-readobj.exe` to `PATH`; the script uses it to validate the Rust host's WinHTTP exports. `lld-link.exe` is also needed for the native build. |
| Rust linking or `cargo build` fails | Confirm the MSVC Rust target, Visual Studio C++ Build Tools, Windows SDK, and `lld-link.exe` are available in the same shell. |
| BepInEx IL2CPP build fails | Check the fork output and the MonoMod packages pinned for this branch in the local source checkout's `docs/NEXUS_SOURCE_AND_BUILD.md`. Use `-RebuildExternalRuntime` when you need the package script to rebuild BepInEx rather than reuse existing outputs. |

The local source checkout's `tools/Inspect-SotfRuntime.ps1 -GameRoot "C:\Games\Sons Of The Forest" -Json` reports installed runtime paths and version drift without rebuilding the package. Its report can contain local paths and game information; review it before sharing.

## The game does not reach the Loader console

Check these files in the game installation, in order:

1. `OpenACAI/Runtime/openacai-native-host.log` and `openacai-native-host-state.json`. The Rust host records attachment and hostfxr bootstrap failures here.
2. `openacai-bootstrap.log` in the game root and `OpenACAI/Runtime/openacai-bootstrap-state.json`, if the managed entry point ran.
3. `BepInEx/plugins/OpenACAILoader/openacai-il2cpp-hook-state.json`, if the BepInEx IL2CPP bridge reached its hook setup. The local source checkout's runtime guide describes `runtimeInvokePatched`, provider selection, and chainloader state.

Confirm that `winhttp.dll`, `doorstop_config.ini`, and the package's `dotnet/` folder are beside `SonsOfTheForest.exe`, and that the configured hostfxr, runtime config, and bootstrap assembly paths exist. Use files from one package build together; mixing the .NET 10 and experimental .NET 11 layouts can break startup. The local source checkout's `docs/SOTF_RUNTIME_COMPATIBILITY.md` records the startup boundaries.

## The Loader starts, but a mod does not appear

Check `OpenACAI/Runtime/openacai-loader-state.json` and `openacai-chainloader-state.json` for startup and inventory status. The package also keeps a compatibility state mirror under `BepInEx/plugins/OpenACAILoader/`.

For a native mod, compare its layout with the local source checkout's `examples/WorldConditions/README.md`: both `openacai.mod.json` and the named assembly belong under one directory in `OpenACAI/Mods/`. Its manifest must name the real assembly, entry type, and entry method. Build it against the Core assembly that matches the installed Loader, then restart the game after changing package files. The example has compiled locally, but its loading and UI behavior have not yet been verified in game; a successful build is not proof that its menu will appear.

Legacy RedLoader mods use `Mods/`, and BepInEx plugins use `BepInEx/plugins/`. Their compatibility status is reported separately from native mod hosting. Consult the Loader state before assuming a missing item is an SDK problem.

## When asking for help

Include the Loader manifest version, branch or commit, the first failing build message, and which startup state files were produced. Remove account names, local paths, server details, logs unrelated to the issue, and any private Admin data before sharing diagnostics publicly.
